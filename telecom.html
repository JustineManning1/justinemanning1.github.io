The analysis

Problem

Churn was rising and the default answer was "cut prices." A blanket discount would cost millions against a cause nobody had verified.

Approach

Joined churn events to support-ticket history, segmented by plan type, and found churn concentrated in month-to-month accounts with repeated service issues.

Decision enabled

Month-to-month churn climbed past 5% while contract plans stayed flat. The April retention offer — aimed only at high-ticket month-to-month accounts — cuts it nearly in half.

Modeled impact: ~$1.8M/yr revenue retained vs. blanket-discount cost avoided

The SQL behind this view

These queries run against the raw CSV in this repo (load it into SQLite or DuckDB). The dashboard's aggregates are what these queries return.

SQL · Churn by plan and ticket bandSQLite / DuckDB
SELECT plan,
       CASE WHEN support_tickets >= 3 THEN '3+ tickets'
            WHEN support_tickets >= 1 THEN '1-2 tickets'
            ELSE 'No tickets' END AS ticket_band,
       ROUND(100.0 * AVG(churned), 2) AS churn_pct,
       COUNT(*) AS account_months
FROM telecom_accounts
GROUP BY plan, ticket_band
ORDER BY plan, churn_pct DESC;
SQL · Revenue at risk ranking (window fn)SQLite / DuckDB
SELECT month, plan,
       SUM(arpu_usd * churned) AS revenue_lost,
       RANK() OVER (PARTITION BY month
                    ORDER BY SUM(arpu_usd * churned) DESC) AS loss_rank
FROM telecom_accounts
GROUP BY month, plan
QUALIFY loss_rank = 1;

The Power BI translation

The same model expressed as DAX measures — how this dashboard is built when the delivery target is Power BI instead of the web.

Power BI · Churn rate measureDAX
Churn % =
DIVIDE (
    CALCULATE ( COUNTROWS ( Accounts ), Accounts[churned] = 1 ),
    COUNTROWS ( Accounts )
) * 100
Power BI · High-risk account flagDAX
High Risk Accounts =
CALCULATE (
    DISTINCTCOUNT ( Accounts[account_id] ),
    Accounts[support_tickets] >= 3,
    Accounts[plan] = "Month-to-month"
)
