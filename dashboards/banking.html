The analysis

Problem

Portfolio delinquency was drifting up. Tightening approvals across the board would choke growth to fix a problem that might live in one segment.

Approach

Segmented roll rates by risk tier and utilization band, identified near-prime + high-utilization as the driver, and targeted early-warning outreach at that intersection.

Decision enabled

Near-prime delinquency climbed for seven straight months while prime barely moved — the stress was segment-specific, not economy-wide. March outreach bends the curve within two cycles.

Modeled impact: ~$2.4M/yr in avoided charge-offs at steady origination volume

The SQL behind this view

These queries run against the raw CSV in this repo (load it into SQLite or DuckDB). The dashboard's aggregates are what these queries return.

SQL · Delinquency by segment and utilization bandSQLite / DuckDB
SELECT segment,
       CASE WHEN utilization_pct > 80 THEN '80%+'
            WHEN utilization_pct > 50 THEN '51-80%'
            ELSE '0-50%' END AS util_band,
       ROUND(100.0 * AVG(delinquent_30d), 2) AS dq_pct,
       COUNT(*) AS account_months
FROM banking_accounts
GROUP BY segment, util_band
ORDER BY segment, dq_pct DESC;
SQL · Seven-month delinquency trend (window fn)SQLite / DuckDB
SELECT month, segment,
       ROUND(100.0 * AVG(delinquent_30d), 2) AS dq_pct,
       ROUND(AVG(100.0 * delinquent_30d) OVER (
           PARTITION BY segment ORDER BY month
           ROWS BETWEEN 2 PRECEDING AND CURRENT ROW), 2) AS dq_3mo_avg
FROM banking_accounts
GROUP BY month, segment;

The Power BI translation

The same model expressed as DAX measures — how this dashboard is built when the delivery target is Power BI instead of the web.

Power BI · Delinquency measureDAX
Delinquency % =
DIVIDE (
    CALCULATE ( COUNTROWS ( Accts ), Accts[delinquent_30d] = 1 ),
    COUNTROWS ( Accts )
) * 100
Power BI · Outreach trigger listDAX
Outreach List =
CALCULATE (
    DISTINCTCOUNT ( Accts[account_id] ),
    Accts[segment] = "Near-prime",
    Accts[utilization_pct] > 80
)
