The analysis

Problem

Blended return rate looked "normal for retail," but margin kept eroding and no one could say which products were responsible.

Approach

Decomposed returns by category and reason code, isolated apparel sizing as the driver, and modeled the margin impact of a size-guide intervention.

Decision enabled

Apparel returns climbed to ~22% while other categories held steady — sizing, not product quality. After the April size-guide launch, apparel returns fall by more than a third.

Modeled impact: ~$310K/yr in avoided return processing + recovered margin

The SQL behind this view

These queries run against the raw CSV in this repo (load it into SQLite or DuckDB). The dashboard's aggregates are what these queries return.

SQL · Return rate by category and monthSQLite / DuckDB
SELECT category,
       strftime('%Y-%m', order_date) AS month,
       ROUND(100.0 * AVG(returned), 1) AS return_rate_pct,
       COUNT(*) AS orders,
       ROUND(SUM(revenue_usd), 0) AS revenue
FROM ecommerce_orders
GROUP BY category, month
ORDER BY category, month;
SQL · Margin recovered after the fix (window fn)SQLite / DuckDB
WITH monthly AS (
  SELECT category, strftime('%Y-%m', order_date) AS month,
         AVG(returned) AS ret_rate, SUM(revenue_usd) AS rev
  FROM ecommerce_orders GROUP BY 1, 2)
SELECT month, ret_rate,
       ret_rate - LAG(ret_rate) OVER (PARTITION BY category ORDER BY month) AS mom_change,
       ROUND(rev * (FIRST_VALUE(ret_rate) OVER w - ret_rate), 0) AS est_margin_recovered
FROM monthly WHERE category = 'Apparel'
WINDOW w AS (PARTITION BY category ORDER BY month
             ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED PRECEDING);

The Power BI translation

The same model expressed as DAX measures — how this dashboard is built when the delivery target is Power BI instead of the web.

Power BI · Return rate measureDAX
Return Rate % =
DIVIDE (
    CALCULATE ( COUNTROWS ( Orders ), Orders[returned] = 1 ),
    COUNTROWS ( Orders )
) * 100
Power BI · Returns vs pre-fix baselineDAX
Returns vs Baseline =
VAR Baseline =
    CALCULATE ( [Return Rate %],
        DATESBETWEEN ( 'Date'[Date], DATE(2025,8,1), DATE(2026,3,31) ) )
RETURN [Return Rate %] - Baseline
